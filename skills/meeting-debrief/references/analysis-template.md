# Meeting Debrief Analysis Template

Produce the debrief in this order. Every section is mandatory for 1:1s and strategy sessions. Adapt or compress for lighter meeting types (see SKILL.md Step 3).

---

## 1. TL;DR

3-5 bullets maximum. Written for someone who will read nothing else. Each bullet must be self-contained and actionable or decision-relevant.

Format:
```
## TL;DR

- **[Topic]:** [What happened + so what]
- **[Topic]:** [What happened + so what]
- **[Urgent]:** [Time-sensitive item if any]
```

Rules:
- Lead each bullet with the topic in bold, not a verb
- Include the "so what" — not just "discussed X" but "discussed X, agreed to Y, you need to do Z"
- If there's a time-sensitive item, flag it with **[Urgent]** and put it last so it stands out
- No filler bullets. If only 3 things mattered, write 3 bullets.

---

## 2. Meeting Context

One-line metadata block:

```
**[Meeting Name]** | [Date] | [Duration estimate] | Speakers: [names]
**Type:** [1:1 / Group Sync / Strategy / Standup / External]
**Tone:** [1-3 words: e.g., "Collaborative and candid" / "Tense, unresolved" / "Surface-level, rushed"]
**Signal-to-Noise:** [High / Medium / Low] — [brief note, e.g., "~80% substantive, minimal small talk"]
```

---

## 3. Topics Covered

One subsection per distinct topic discussed. Order by importance, not chronology.

For each topic:

```
### [Topic Name]

**What was said:**
[Concise summary of the discussion — who said what, positions taken, information shared. Use speaker names. Include timestamps from transcript when referencing specific quotes.]

**Decisions made:**
- [Decision, if any. "None" if the topic was discussed but nothing was decided.]

**Still open:**
- [Open questions, unresolved disagreements, deferred items]

**My read:**
[Your genuine analysis. What does this mean? What's the subtext? What should the user be thinking about that wasn't said aloud? Is someone hedging? Is a commitment soft? Is there organizational context that makes this more significant than it sounds?]
```

---

## 4. Decision Log

Two-column summary — what was locked in vs. what's still floating:

```
| Decided | Open / Deferred |
|---------|----------------|
| [Decision 1] | [Open question 1] |
| [Decision 2] | [Deferred item 1] |
```

If something was presented as decided but has weak commitment signals (hedging language, no timeline, no owner), flag it in the "Open" column with a note.

---

## 5. Commitment Tracker

Two parts: new commitments from this meeting, and accountability check on past commitments.

### New Commitments

| Who | Commitment | Deadline | Confidence |
|-----|-----------|----------|------------|
| [Name] | [What they committed to] | [Date if stated, "Unspecified" if not] | [High/Medium/Low — based on language strength, track record, and specificity] |

**Confidence scoring guide:**
- **High:** Specific action + timeline + this person has delivered before
- **Medium:** Agreed to do it but vague on when, or has a pattern of partial follow-through
- **Low:** Acknowledged but deflected, no timeline, or contradicted by body language / hedging

### Past Commitment Check

Cross-reference action items from the last 2-3 meetings with this person. For each:

```
- [Past commitment] — **Status:** [Completed / In progress / No mention / Appears stalled]
  [Brief note on evidence]
```

If past commitments were not raised and appear stalled, flag them in the Unsaid Topics section.

---

## 6. Dynamics & Subtext

Read between the lines. This section is where the "second brain" earns its keep.

Cover any of these that are relevant:

- **Influence flow:** Who drove the conversation? Who set the agenda? Who made concessions? Who deferred to whom?
- **Relationship signals:** Is this relationship strengthening, stable, or showing friction? Evidence?
- **Political context:** Are there organizational dynamics at play (reorgs, competing priorities, turf issues)?
- **What they said without saying it:** Hedges, deflections, things framed carefully. What's the real message?
- **Energy and engagement:** Were both parties engaged throughout, or did someone check out on certain topics?
- **Trust indicators:** Did they share information freely, or was information guarded?

Write as bullet points with brief evidence from the transcript. Don't speculate wildly — but don't be timid either. The user wants the honest read.

---

## 7. Unsaid Topics

Topics that were discussed in previous meetings but not raised in this one — and probably should have been. Also topics the user might want to raise next time based on context.

```
### Dropped Threads
- **[Topic from past meeting]** — Last discussed [date]. Status unknown. Consider raising next time.

### Worth Raising Next Time
- **[Topic]** — [Why this matters and why now is the right time]
```

If there are no dropped threads or suggested topics, omit this section entirely rather than padding it.

---

## 8. Risk Radar

Things that could go wrong based on what was discussed. Be specific and cite evidence.

```
| Risk | Likelihood | Impact | Evidence |
|------|-----------|--------|----------|
| [What could go wrong] | [High/Med/Low] | [What breaks if it happens] | [Why you think this — quote or pattern] |
```

Focus on risks that are actionable — things the user can mitigate. Don't flag risks they can't influence.

---

## 9. Recommendations

Prioritized, concrete, with a specific next action and timeframe. No vague "follow up" or "keep an eye on."

```
1. **[Action verb] [specific thing]** — [Why, and by when]
2. **[Action verb] [specific thing]** — [Why, and by when]
3. **[Action verb] [specific thing]** — [Why, and by when]
```

Rules:
- Maximum 5 recommendations. If everything is a priority, nothing is.
- Each must name a specific action, not a general principle
- Include a suggested timeframe (today, this week, before next 1:1, etc.)
- Order by urgency, then importance

---

## 10. Follow-up Fuel

Pre-drafted content the user can use or adapt. Pick whichever of these are most useful:

**Option A: Talking points for the next meeting**
```
For your next meeting with [person], consider leading with:
1. [Topic] — [Specific question or framing]
2. [Topic] — [Specific question or framing]
```

**Option B: Draft follow-up message**
```
Draft Slack/email to [person]:

[Pre-written message the user can send as-is or edit]
```

**Option C: Questions to ask others**
```
To get ahead of [risk/topic], consider asking:
- [Person]: [Question]
- [Person]: [Question]
```

Only include options that add genuine value. One strong follow-up is better than three weak ones.
