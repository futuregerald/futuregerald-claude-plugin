## 2. Prism Memory (Search-First & Auto-Save)

Call directly with `call_mcp_tool`, `ServerName: "prism"`. Do not read the schema JSONs.

- **Search Prism FIRST:** Before grepping, reading codebase-memory, or searching the web for any prior info, memories, decisions, bug history, or context, search Prism FIRST (`knowledge_search` / `session_search_memory`) **without** a `project` filter so cross-project memories surface first; then verify against live code.
- **Project key:** `basename $(git rev-parse --path-format=absolute --git-common-dir 2>/dev/null | sed 's/\/\.git$//')`, lowercased, or `"dev"` outside a repo. Use this `<project>` key for `session_load_context` and all writes.
- `session_load_context` → `{"project": "<key>", "level": "standard"}`. Turn 1 only, and only for repo engineering, debugging, architecture, or resuming work. Skip for reports, debriefs, 1:1 prep and one-off lookups.
- `session_save_ledger` → `{"project", "conversation_id", "summary" (1–3 sentences), "files_changed", "decisions", "todos"}`. After coding, debugging, planning, grooming or PR review.
- `session_save_handoff` → `{"project", "expected_version": <int>, "last_summary", "open_todos", "key_context", "active_branch"}`. When project state or TODOs change.
- `session_save_experience` → `{"project", "event_type": "correction|learning|failure|success", "context", "action", "outcome", "correction"}`.

## 3. review-lens Corpus Check

Applies only to organizations listed under `review_lens.orgs` in [references/config.md](references/config.md) (never to `review_lens.exclude_orgs`). Read `references/config.md` for `analyzer_dir`, `venv_bin`, `binary`, `db`, and `<org>`. Run it yourself after the fresh reviewer returns; never put it in the reviewer's prompt.

```bash
AN="<analyzer_dir>"; RL="$AN/<binary>"
export PATH="<venv_bin>:$PATH"
$RL similar --concept "<one approach from the plan>" --k 8 --repo <org>/<repo> --db "$AN/<db>"
$RL similar --concept "<approach>" --k 5 --reviewer <login> --repo <org>/<repo> --db "$AN/<db>"
git show HEAD:<file> | $RL similar --code - --k 8 --repo <org>/<repo> --db "$AN/<db>"
git show <sha> -- <file> | $RL similar --code - --k 8 --repo <org>/<repo> --db "$AN/<db>"
```

Run both `--code` and `--concept` every time. Use `--json | jq` to keep output small; put multi-query loops in a script file. Cite matched objections (PR, reviewer, what they said) and fix or record why they don't apply. Report which queries ran, even with no match.

## 4. Code Search Hierarchy

- **Existence and shape** ("does X exist", "where is it defined") → graph/index first: `search_graph`, `query_graph`, `get_code_snippet`, `get_architecture`, `search_code`. Use `--query` (BM25) or `--name-pattern`, never `--semantic-query`.
- **Reachability** ("who calls this", "is it dead", "what breaks") → `git grep -n` first in git repos (falls back to `grep -rn` with `--exclude-dir` outside git). `trace_path` misses Rails dynamic dispatch (`send`, `constantize`, organizer lists, string-named jobs) and is never a valid caller list.
- **Before citing graph results:** one batched `check_index_coverage` call with every path you will cite. If partial, stale or unknown, read the file.
- **Graphify:** if `graphify-out/graph.json` exists, use `graphify query|path|explain`; run `/graphify . --update` before committing code changes.
- `rg` is not installed on this machine; use `git grep -n` (or `grep -rn` with `--exclude-dir`).

### 5b. Controlled Native `swarm` Routing (Three Bounded Modes Only)

Unlike `invoke_subagent`, Antigravity's native `swarm` (`swarm{action: "add", model: "..."}`) accepts exact model + effort IDs (`gemini-4-neon-medium`, `gemini-4-carbon-high`, `gemini-4-carbon-medium`, `gemini-4-argon-medium`, `gemini-4-hydrogen-high`, `gemini-4-hydrogen-low`). Observed 7-day Turn-1 floors are `29.3k` tokens for Gemini 4 `swarm` workers (`Neon`, `Carbon`, `Argon`, `Hydrogen`; `~117k` = `4 × 29.3k` 4-worker Peer-Pipeline Swarm boot floor for both `/start` and `/start-small`), compared to `22.7k` (`[read_file]`) and `24.8k` (`implementer`) in `invoke_subagent` (`claude-opus-5-5-high` at `45.0k` is strictly opt-in and MUST NEVER be spawned unless the user explicitly asks for an Opus review in chat). Use `swarm` **strictly** in the three bounded modes below:

#### Mode A: One-Shot `gemini-4-carbon-high` Adversarial Reviews When UI != `Carbon High`
When the UI is on **`Carbon Medium`** (default) or **`Argon`** and you reach a non-trivial Phase 3½ `plan-review` or standalone pre-PR Phase 8 `comprehensive-code-review`:
1. **Stage uncommitted edits & spawn without `monitor` or `narrator`:** Because `swarm` workers do **not** enforce `tools: [read_file]` at the harness level and `workspace: "inherit"` shares the live working tree, stage (`git add`) or checkpoint uncommitted work first. Then call `swarm{action: "add", name: "plan-rev", model: "gemini-4-carbon-high", workspace: "inherit", brief: "..."}` (or in Phase 8, add `code-rev` and `sec-rev` in the same turn). **Never** add a `monitor` or `narrator` for one-shot reviews. Because killed worker names cannot be reused in the same conversation, suffix `-2`, `-3`, etc. (`plan-rev-2`, `code-rev-2`) on later streams.
2. **Strict read-only brief (prompt-level mitigation):** State in `brief` that the worker MUST read `~/.gemini/config/plugins/antigravity-subagents/agents/<role>.md` and all indexed chunks of `/tmp/subagent-context-<project>-<stream>.md` (or the plan file) in 1 Turn-1 parallel `read_file` batch, batch follow-up reads `5–10` files/turn (`±40` lines around narrow call sites), use **only** `read_file` and `post_message` (**strictly forbidding** `run_command`, `edit_file`, `write_file`, `swarm`, and any git or working-tree mutations such as `git checkout`, `restore`, `reset`, `clean`, `stash`, or `rm`), and post its structured findings once beginning with `@coordinator` (never `@all` or `@other-reviewer`).
3. **End turn, read, and immediately `kill`:** On the turn that creates the first `swarm` worker, end your turn immediately (`read_board` and `swarm_wait` arrive on the next turn after wakeup). Once all spawned reviewers have posted (`swarm_wait{since: N}` if waiting on the second parallel reviewer), read the findings via `read_board` and immediately terminate every reviewer with `swarm{action: "kill", name: "..."}`.

#### Mode B: Peer-Pipeline Swarm (`/start`, `/begin`, `/start-small`, `/peer-pipeline-swarm`) & Parallel Implementation Streams
1. **When to use:** Use [`peer-pipeline-swarm`](../peer-pipeline-swarm/SKILL.md) for hands-off Phases 4–9 under `/start`, `/begin`, `/start-small`, or `/lifecycle`, or for `≥3` independent parallel implementation streams (`/swarm`, `/teamwork`). (Trivial `<5-turn, ≤2-file` changes may run inline + `invoke_subagent` review.)
2. **Pin `monitor` to `gemini-4-hydrogen-low` (`0.2×`, fallback `gemini-3.8-flash-low`):** Stall checks are mechanical `#seq` comparisons (`last_read_seq` vs `last_post_seq`); never burn Carbon/Argon reasoning tokens on `*/3 * * * *` cron ticks, and never merge `monitor` with `ops`.
3. **Explicit role-based model pinning:**
   - **Coordinator / Planner:** active UI model (`gemini-4-carbon-medium` default; `gemini-4-argon-medium` optional for small tasks)
   - **Stream Authors (`impl`, `workspace: "share"`):** **`gemini-4-neon-medium`** under both `/start` and `/start-small` (default Antigravity implementer)
   - **Adversarial Code-Quality, Security & SQL Verifiers (`code-rev`, `sec-rev`, `sql-rev`, `workspace: "inherit"`, read-only by brief):** **`gemini-4-carbon-high`** under both `/start` and `/start-small` (**sole default reviewer** — NEVER spawn or fail over to `claude-opus-5-5-high` unless the user explicitly asks for an Opus review in chat)
   - **Stall Monitor (`monitor`):** `gemini-4-hydrogen-low` (fallback `gemini-3.8-flash-low`)
4. **Pointer-only board posts (≤5 lines; zero diffs or logs on the board):** Write diffs and test output to `/tmp/subagent-context-<project>-<stream>.md` on disk (via `python3 ~/.gemini/config/skills/subagent-driven-development/scripts/build_subagent_context.py`) and post only `@target`, commit SHA/branch, context file path, `#seq` references, and exit status.
5. **Per-stream channels (when `action: "channel"` is exposed) + `@mention` discipline:** When the `swarm` tool exposes `action: "channel"`, create `#<stream>` channels (`swarm{action: "channel", op: "create"}`) for each `author + verifier` pair and keep `main` silent after startup; regardless of channel support, never post `@all` — authors `@verifier`, verifiers `@author` on findings, and ping `@coordinator` only when green or blocked.
6. **One phase per worker, then merge + `kill`:** Land the `workspace: "share"` branch into the working copy, `kill` the finished worker, and spawn fresh workers (with `-2`/`-3` suffixes if needed) for the next phase rather than replaying a 100k+ Phase 1 transcript.

## 6. Breaker Hook and Baton-Pass Mechanics

Hook: `~/.gemini/config/hooks/autonomous_breaker.py` (registered in `~/.gemini/config/hooks.json`). Rules and defaults:

| Rule | Fires when | Mode |
|---|---|---|
| DUP | identical tool call repeated within a 6-step window | enforce |
| EXPLORE | helper exceeds `BREAKER_SUBAGENT_EXPLORE_MAX` exploratory calls (opt-in; default `0` / disabled) | enforce (when cap > 0) |
| STRIKES | 4 consecutive test failures | enforce |
| PROBE | 3rd inline `python3 -c` probe of the same file | enforce |
| TRUELOOP | 3rd re-read of ≥50% already-read lines, or same command, within 20 planner steps, no edit between | enforce |
| H1 | authorized main session makes a 7th code edit without dispatching a helper | enforce |
| H2 | helper reaches `BREAKER_SUBAGENT_STEP_MAX` planner turns (opt-in; default `0` / disabled) | enforce (when cap > 0) |
| BATON | 3-way context partition (`input_tokens + cache_read_tokens + output_tokens` + trailing bytes ÷ 4 since compaction): `350k` swarm-worker cap (+25k `/tmp/*.md` WIP unlock, including `SYSTEM_MESSAGE`-only workers), `350k` (`SUBAGENT_TOKEN_CAP`) `invoke_subagent` cap (+25k `ACTIVE_CONTEXT.md` / `/tmp/*.md` cleanup unlock + `swarm status/kill` exemption -> `BATON_CONTINUE`), and `310k` warn / `350k` block (+50k `ACTIVE_CONTEXT.md` unlock + `send_message` `<450k` relay exemption -> auto-spawn same-chat `TypeName: "self"` Child Orchestrator; `450k` hard ceiling for manual fresh chat on `512k` compaction window) | enforce |

**Baton-pass (Same-Chat Child Orchestrator Auto-Chaining by default):** when a Child Orchestrator hits `350k` or Root hits `310k`/`350k` (`<450k`), follow the `baton-pass` skill:
1. **Without `swarm` (`subagent` / `inline`):** Fold any `/tmp/subagent-context-*.md` notes (and if a standalone sleeping `ops` worker was spawned, call `swarm{action: "kill", name: "ops"}` first), write `~/.gemini/handoffs/<project-key>/<YYYY-MM-DD-HHMMSS>-<slug>-ACTIVE_CONTEXT.md` (`Execution Mode: subagent | inline`, mirrored to the brain dir), and save Prism `session_save_handoff`.
2. **With `swarm` (`peer-pipeline-swarm` / native `swarm`):** Write `ACTIVE_CONTEXT.md` first at `>=350k` to unlock `+50k` tokens in Root (or `+25k` in a `TypeName: "self"` Child Orchestrator; `read_board`, `post_message`, `swarm{action: "status"|"kill"}`, `/tmp/*.md` / `ACTIVE_CONTEXT.md` reads, and Root `send_message` `<450k` stay exempt). Run `git fetch "<SHARE_ROOT>" "<SHA>" && git rev-parse --verify "<SHA>^{commit}"` and merge or anchor `git branch -f "baton/<stream>" "<SHA>"` **before** calling `swarm{action: "kill"}` on all workers (including `monitor` and any active/waiting `ops` / `ops-N` worker), then update `ACTIVE_CONTEXT.md` (`Execution Mode: swarm`) and save Prism `session_save_handoff`.
3. **Auto-Relay vs. Manual New Chat:** A Child Orchestrator returns `BATON_CONTINUE: <path>` via `send_message` and Root **immediately spawns a fresh `invoke_subagent(TypeName="self", Model="inherit")` Child Orchestrator in the SAME chat** (and if Root itself hit `310k`/`350k` `<450k`, Root spawns the `TypeName: "self"` Child Orchestrator directly in the SAME chat). Emit the manual `Ingest ~/.gemini/handoffs/<project-key>/<YYYY-MM-DD-HHMMSS>-<slug>-ACTIVE_CONTEXT.md and continue from Pending Steps.` prompt for a new chat **only** when Root `estimate >= 450000` or when explicitly requested by the user.

Escape hatch: `BREAKER_BATON_MODE=log`. Writing `ACTIVE_CONTEXT.md` unlocks Root for `+50k` tokens (and Child Orchestrators for `+25k` tokens; `invoke_subagent` and `swarm add` remain denied in Root at `>=450k` near the `512k` compaction ceiling). Swarm workers are exempt from the `310k` warn; if a swarm worker reaches `350k`, writing `/tmp/subagent-context-*.md` unlocks `+25k` tokens to commit WIP in `SHARE_ROOT` and post `@coordinator [blocked] context-cap SHARE_ROOT=<path> SHA=<sha>`.

**Strike escalation:** when an implementer or helper subagent trips STRIKES (or opt-in EXPLORE) it writes its 5-section handoff with the failing diff and test output; the orchestrator diagnoses in one turn and resolves without stopping for confirmation.
