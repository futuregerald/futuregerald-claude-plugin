# Development Lifecycle (`/lifecycle`)

Execute the 12-phase workflow for code changes, holding each phase gate before advancing to the next. Create and maintain a checklist of all 12 phases (via `TaskCreate` or the active harness's task checklist) and check off each phase only when its gate is verified with evidence.

## Exemptions

- **Only pure doc updates and `git revert` skip the lifecycle.**
- **Every code change gets a written plan (Phase 3), including one-line fixes.**
- **Only Phase 3½ (`plan-review`) may be skipped for a trivial change** with an obvious, self-contained blast radius that does not alter any contract other callers depend on.

## Phase Sequence & Gates

| # | Phase | Action | Skill / Tool | Gate |
|---|---|---|---|---|
| **0** | **Shape** | **New or user-facing work (feature, product, page, design, PRD):** Run `craftsmans-wisdom` automatically (unless a brief was already confirmed this session). After the brief is confirmed, offer `future-grilling` on the details, then run `write-a-prd` or `brainstorming` if needed. **Work too big for one session** (decisions needing research, prototypes or several sittings): run `future-wayfinder` from the brief instead of `future-grilling`; Phase 1 starts once its map is clear and handed to `write-a-prd` and the roadmap. **Internal technical work (refactor, dependency bump, small fix):** Ask once per session whether to skip Phase 0 or run `future-grilling` on open decisions. | `craftsmans-wisdom`, `future-grilling`, `future-wayfinder` (multi-session work), `write-a-prd`, `brainstorming`, `grilling-page` (if ≥3 independent questions) | Brief confirmed by the user, or Phase 0 explicitly skipped for internal technical work |
| **0½** | **UI Design** | **Net-new pages, new apps, major/non-trivial changes to existing UI pages, or anytime requested:** Run `ui-design` (`huashu-design` 3-direction gate) to generate 3 distinct high-fidelity prototypes of the same thing (Style Roulette · Benchmark Reference · Dream Studio) on a single interactive HTML page (`design-demos/index.html`), open it in the browser, and stop until the user picks a direction (or mix-and-match). Record the selection in `direction-approved.md`. | `ui-design`, `huashu-design` | User selected a UI direction (`direction-approved.md`), or N/A for backend-only / trivial UI tweaks |
| **1** | **Receive** | Understand the task and constraints. Suggest a tracker ticket (per local org rules) and create it only after the user agrees. Read repo conventions (`CONTRIBUTING.md`, `docs/adr/`, `*GUIDELINES*.md`, `*PATTERNS*.md`). | — | Task understood; checklist created |
| **2** | **Trace** | Reconstruct the call chain in both directions for every symbol touched. **Upward:** every direct and transitive caller out to controller, job, rake task, CLI, or API, and what part of the contract each relies on. **Downward:** callees, DB/HTTP/queue/cache side effects, transactions, exceptions. **Invisible edges:** grep deliberately for `send`, `public_send`, `constantize`, serializers, callbacks, string-named jobs. Use graph/index tools for existence/shape; use `git grep -n` for reachability. | — | Every caller named, with what it expects |
| **3** | **Plan** | Write the implementation plan using `writing-plans` (never commit it; Medium effort default, High effort for net-new multi-layer architecture/migrations). Inspect repo lint/wording scripts (`package.json`, `Makefile`, `scripts/check-*.mjs`) and exact shared contract definitions before freezing `PLAN.md`. Required sections: Goal · **Affected Callers** (breaking callers with consequence + untested unbroken callers) · Approach · Step-by-step TDD tasks with exact file paths, signatures, test cases, and gate commands (never function bodies) · Risks · Rollback · Out of scope. Keep the plan file current in every turn reality moves. | `writing-plans` | Plan file exists with `Affected Callers` & repo gate invariants |
| **3½** | **Plan review** | Dispatch **one** fresh read-only **Adversarial Reviewer** sub-agent (routed via the active harness's root configuration, e.g. `model: "opus"`, `effort: "high"` in `CLAUDE.md`) using `plan-review` (**zero spikes, zero builds or test runs**). **Skip only for trivial changes** with an obvious, self-contained blast radius. Where configured in local org rules, also run the `review-lens` corpus check (`--code` and `--concept`). Fix every CRITICAL and IMPORTANT finding in the plan and verify against the plan diff yourself (never send back for a second review). | `plan-review`, `review-lens` | All CRITICAL/IMPORTANT fixed (or skipped for trivial change) |
| **4** | **Implement** | Before adding any new symbol, run the reuse check (search name and distinctive body tokens) and match the newest sibling file in the same directory (citing `file:line` in the plan). Write pre-traced context to `/tmp/subagent-context-<project>-<stream>.md` and dispatch an **Implementer** sub-agent (routed via the active harness's root configuration, e.g. `model: "sonnet"` in `CLAUDE.md`) following TDD (RED → GREEN → REFACTOR), returning the 4-section handoff: Changes Made · Flawed Assumptions · Carried Risks · Verification Evidence. Write no code comments without asking first. | `test-driven-development`, `subagent-driven-development` | Fast unit tests pass; nothing duplicated; 4-section handoff recorded |
| **5** | **Test** | Run the project's fast unit test command for affected specs in the orchestrator's own shell (`npx vitest run <spec>`, `CGO_ENABLED=0 go test ./<pkg> -run <AffectedTests> -race`, `bundle exec rspec <spec>`). Never run E2E suites or `pretest` multi-builds locally between changes. | — | Zero fast-test failures |
| **6** | **Lint** | Run the project's linter and typecheck in the orchestrator's own shell — fix all offenses. Append passing test/lint output + `git diff` to `/tmp/subagent-context-<project>-<stream>.md`. | — | Zero lint/typecheck offenses |
| **7** | **Simplify** | Review recently changed code for reuse, clarity, and efficiency using `code-simplifier`; apply approved simplifications and re-run fast tests/lint. | `code-simplifier` | Simplified; fast tests/lint green |
| **8** | **Code review** | Run `comprehensive-code-review`: two parallel fresh read-only **Adversarial Reviewer** sub-agents (`code-quality-reviewer` and `security-reviewer`, routed via the active harness's root configuration) reading `/tmp/subagent-context-<project>-<stream>.md` (never re-running tests/builds/E2E), plus the `review-lens` corpus check on the diff (where configured). Fix every CRITICAL and IMPORTANT finding, re-run fast tests, and verify fix rounds with `fix-check` (never a second full review). Delete `/tmp/subagent-context-<project>-<stream>.md` once approved. | `comprehensive-code-review`, `review-lens`, `fix-check` | Approved; temp context file deleted |
| **9** | **SQL review** | Only if database queries, migrations, or ORM mutations changed: audit in a fresh read-only **Adversarial Reviewer** sub-agent (`sql-reviewer`, routed via the active harness's root configuration) for performance, index usage, security, and defensive coding. | `sql-reviewer` agent, `sql-optimization-patterns` | Reviewed (or N/A if no SQL/ORM changes) |
| **10** | **Blast-radius verify** | **Always runs last.** Any code change in Phase 7 (`Simplify`) or Phase 8/9 fix rounds re-opens Phase 10. Walk every row of `Affected Callers` (breaking and untested), **plus the callers of every symbol the final diff touched that the plan did not list**, and verify each with concrete evidence. | — | Every caller verified with evidence |
| **11** | **Commit** | Create a conventional commit (with ticket key where applicable) on a properly named feature branch (never `main`). | — | Commit created |
| **12** | **Handoff** | For user-facing work, run `editor-pass` against the Phase 0 brief before shipping. Present summary of changes. On personal repos configured for auto-PR, push the branch, open the PR using `pull-request-description`, **immediately ask the user if they want to run `/copy-edit` (`copywriting` + `marketing-psychology` report) as soon as the PR is opened so it can run while waiting on CI (`gh pr checks <pr> --watch`)**, and watch CI until green. On org repos, prompt the user to review and push (and offer `/copy-edit` alongside). Never auto-merge. Save Prism `session_save_ledger` and `session_save_handoff`. | `pull-request-description`, `editor-pass`, `copy-edit` (offer when PR is opened while waiting on CI) | User acknowledged (and CI green on auto-PR repos) |
